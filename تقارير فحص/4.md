## 🔧 اليوم الأول: التحضير والنسخ الاحتياطي

### 1.1 نسخة احتياطية كاملة من قاعدة البيانات

**قبل أي شيء، أنشئ نسخة احتياطية:**

```bash
# 1. سجل التاريخ والوقت
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="/var/backups/qaat_erp"

# 2. أنشئ المجلد لو ما موجود
mkdir -p $BACKUP_DIR

# 3. Backup كامل
mysqldump \
    --user=root \
    --password \
    --single-transaction \
    --quick \
    --lock-tables=false \
    --routines \
    --triggers \
    --events \
    qaat_erp > $BACKUP_DIR/qaat_erp_full_$TIMESTAMP.sql

# 4. اضغط النسخة
gzip $BACKUP_DIR/qaat_erp_full_$TIMESTAMP.sql

# 5. تحقق من الحجم
ls -lh $BACKUP_DIR/

# المتوقع: 100MB-1GB حسب حجم البيانات
```

### 1.2 نسخة احتياطية من الكود

```bash
# 1. لو Git موجود
cd /path/to/project
git status                              # تأكد لا يوجد تغييرات غير مرغوبة
git add -A
git commit -m "chore: pre-migration snapshot"
git tag -a pre-refactor-v1 -m "Before STAGE 1-4 refactoring"
git push origin pre-refactor-v1

# 2. نسخة من .env
cp .env .env.backup.$TIMESTAMP

# 3. نسخة من storage (المهم)
tar -czf $BACKUP_DIR/storage_$TIMESTAMP.tar.gz storage/app storage/logs

# 4. نسخة من public (لو فيه ملفات مرفوعة)
tar -czf $BACKUP_DIR/public_$TIMESTAMP.tar.gz public/uploads
```

### 1.3 نسخة احتياطية من إعدادات السيرفر

```bash
# Apache/Nginx config
sudo cp /etc/nginx/sites-available/qaat_erp $BACKUP_DIR/nginx_config_$TIMESTAMP.conf 2>/dev/null || true
sudo cp /etc/apache2/sites-available/qaat_erp.conf $BACKUP_DIR/apache_config_$TIMESTAMP.conf 2>/dev/null || true

# PHP-FPM config
sudo cp /etc/php/8.2/fpm/pool.d/qaat_erp.conf $BACKUP_DIR/phpfpm_$TIMESTAMP.conf 2>/dev/null || true

# Supervisor (queues)
sudo cp /etc/supervisor/conf.d/qaat_worker.conf $BACKUP_DIR/supervisor_$TIMESTAMP.conf 2>/dev/null || true
```

### 3.4 التحقق من صحة الترحيل

**اختبار 1: تطابق الأرصدة**

```sql
-- قارن بين الجدول الجديد والحركات
SELECT
    ib.item_id,
    ib.warehouse_id,
    ib.quantity AS balance_qty,
    COALESCE(movement_qty.calc_qty, 0) AS movement_qty,
    ABS(ib.quantity - COALESCE(movement_qty.calc_qty, 0)) AS diff
FROM inventory_balances ib
LEFT JOIN (
    SELECT
        imd.item_id,
        imd.warehouse_id,
        imd.unit_id,
        imd.type_id,
        SUM(CASE WHEN im.direction = 'in' THEN imd.quantity ELSE -imd.quantity END) AS calc_qty
    FROM inventory_movement_details imd
    JOIN inventory_movements im ON im.movement_id = imd.movement_id
    GROUP BY imd.item_id, imd.warehouse_id, imd.unit_id, imd.type_id
) movement_qty
    ON movement_qty.item_id = ib.item_id
    AND movement_qty.warehouse_id = ib.warehouse_id
    AND (movement_qty.unit_id = ib.unit_id OR (movement_qty.unit_id IS NULL AND ib.unit_id IS NULL))
    AND (movement_qty.type_id = ib.type_id OR (movement_qty.type_id IS NULL AND ib.type_id IS NULL))
WHERE ABS(ib.quantity - COALESCE(movement_qty.calc_qty, 0)) > 0.000001
LIMIT 100;

-- ✅ المتوقع: صفر صف (لا فرق)
```

**اختبار 2: Sequences مُعبَّأة**

```sql
SELECT * FROM sequences;
-- المتوقع: sales_invoice, purchase_invoice, inventory_movement, etc.

-- تحقق من القيم
SELECT
    s.key,
    s.next_value,
    CASE s.key
        WHEN 'sales_invoice' THEN (SELECT MAX(CAST(invoice_number AS UNSIGNED)) + 1 FROM sales_invoices)
        WHEN 'purchase_invoice' THEN (SELECT MAX(CAST(invoice_number AS UNSIGNED)) + 1 FROM purchase_invoices)
        WHEN 'inventory_movement' THEN (SELECT MAX(CAST(display_id AS UNSIGNED)) + 1 FROM inventory_movements)
    END AS expected
FROM sequences s;
-- ✅ المتوقع: next_value = expected
```

**فحص 4: تطابق الأرصدة**

```sql
-- تحقق عشوائي على 100 صنف
SELECT
    ib.item_id,
    ib.warehouse_id,
    ib.quantity AS balance_qty,
    COALESCE(m.qty, 0) AS movement_qty,
    ABS(ib.quantity - COALESCE(m.qty, 0)) AS diff
FROM inventory_balances ib
LEFT JOIN (
    SELECT
        imd.item_id,
        imd.warehouse_id,
        imd.unit_id,
        imd.type_id,
        SUM(CASE WHEN im.direction = 'in' THEN imd.quantity ELSE -imd.quantity END) AS qty
    FROM inventory_movement_details imd
    JOIN inventory_movements im ON im.movement_id = imd.movement_id
    WHERE im.deleted_at IS NULL
    GROUP BY imd.item_id, imd.warehouse_id, imd.unit_id, imd.type_id
) m ON m.item_id = ib.item_id
    AND m.warehouse_id = ib.warehouse_id
    AND (m.unit_id = ib.unit_id OR (m.unit_id IS NULL AND ib.unit_id IS NULL))
    AND (m.type_id = ib.type_id OR (m.type_id IS NULL AND ib.type_id IS NULL))
WHERE ABS(ib.quantity - COALESCE(m.qty, 0)) > 0.000001
LIMIT 100;
-- ✅ المتوقع: صفر صف
```

**فحص 5: ترقيم متسلسل بدون فجوات**

```sql
-- sales_invoices
SELECT
    MIN(CAST(invoice_number AS UNSIGNED)) as min_num,
    MAX(CAST(invoice_number AS UNSIGNED)) as max_num,
    COUNT(*) as total
FROM sales_invoices
WHERE deleted_at IS NULL;
-- تحقق: min + total - 1 = max (بدون فجوات)
```

## 🔄 خطة Rollback

**إن حدث خطأ، ارجع بهذا الترتيب:**

### Level 1: Rollback Migrations فقط

```bash
# على سيرفر الإنتاج
php artisan down

# ارجع Migration الأخيرة
php artisan migrate:rollback --step=1

# لو أثر على جداول، ارجع كل migrations المرحلة:
php artisan migrate:rollback --step=5

php artisan up
```

### Level 2: Rollback الكود فقط

```bash
cd /var/www/qaat_erp

# ارجع للـ tag السابق
git checkout pre-refactor-v1

# أعد بناء caches
composer install --no-dev
php artisan config:cache
php artisan route:cache
```

### Level 3: Rollback DB كامل

```bash
# 1. فعّل الصيانة
php artisan down

# 2. ارجع DB من النسخة الاحتياطية
gunzip < /var/backups/qaat_erp/pre_deploy_TIMESTAMP.sql.gz | \
    mysql -u root -p qaat_erp

# 3. ارجع الكود
git checkout pre-refactor-v1
composer install --no-dev
php artisan config:cache

# 4. ارفع الصيانة
php artisan up
```

### Level 4: Rollback Staging First

**القاعدة الذهبية:** **لا ترجع الإنتاج قبل اختبار الـ Rollback على Staging.**

5. **التوثيق جزء من النشر** — سجّل كل خطوة والنتيجة.

6. **اختبار Rollback على Staging أولاً** — لا تكتشف مشاكل الاستعادة في الإنتاج.

7. **بعد النشر:** أبقِ النسخة الاحتياطية 30 يوماً على الأقل.

8. **Staging يبقى فعّالاً** — للاختبارات المستقبلية.
