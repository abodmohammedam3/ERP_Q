## 🎯 المبادئ الأساسية

### 1. Single Source of Truth — مصدر واحد للحقيقة

**لكل نوع من البيانات مصدر واحد فقط:**

| البيانات | المصدر | ملاحظة |
|----------|--------|--------|
| أرصدة المخزون (Audit) | `inventory_movements + details` | السجل التاريخي الكامل |
| أرصدة المخزون (Query) | `inventory_balances` | Materialized View يُحدَّث تلقائياً |
| القيود المحاسبية | `Journal_Entries + Lines` | المصدر الحقيقي |
| أرصدة الحسابات | تُحسب من `Journal_Entries` | لا جدول منفصل |
| أرقام المستندات | `sequences` | ذري (Atomic) |
| بيانات العملاء/الموردين | `customers` + `characcount` | العميل مرتبط بحساب |

**القاعدة:** لا نُخزّن نفس البيانات في مكانين. لو احتجنا نسخة سريعة، نُسميها **Cache** أو **Materialized View** ونوثّق تزامنها.

---

### 2. Separation of Concerns — فصل الاهتمامات

**كل طبقة لها دور واحد فقط:**

```
┌─────────────────────────────────────────┐
│  HTTP Layer (Controllers + Requests)    │  ← استقبال + تحقق
├─────────────────────────────────────────┤
│  Business Layer (Services + Enums)      │  ← منطق العمل
├─────────────────────────────────────────┤
│  Data Layer (Models + Repositories)     │  ← الوصول للبيانات
├─────────────────────────────────────────┤
│  Presentation Layer (Blade + JS)        │  ← العرض
└─────────────────────────────────────────┘
```

**القواعد الصارمة:**

| الطبقة | ✅ تفعل | ❌ لا تفعل |
|--------|---------|-----------|
| Controller | استدعاء Service، إرجاع رد | `DB::`، منطق عمل، تحقق |
| FormRequest | تحقق من المدخلات | منطق عمل، DB |
| Service | منطق العمل، transactions | `Request` مباشر، View |
| Model | العلاقات، Scopes، Casts | منطق عمل، HTTP |
| Observer | ردود فعل على الأحداث | منطق معقد |
| Blade | عرض فقط | منطق، استعلامات DB |
| JS | تفاعل، AJAX | منطق محاسبي |

---

### 3. DRY — لا تكرر نفسك

**كل منطق يتكرر في 2+ أماكن → استخرجه:**

| نوع التكرار | الحل |
|-------------|------|
| منطق عمل | `Service` أو `Action` |
| تحقق | `FormRequest` + `Rule` |
| ردود API | `BaseController` methods |
| Transactions | `BaseService::transaction()` |
| تنسيق JSON | `API Resource` |
| سلوك عام | `Trait` |
| عمليات DB متكررة | `Scope` أو `Repository` |
| عرض مشترك | `Blade Component` |

**مثال حي — `validateStockAvailability`:**

```php
// ❌ مكرر في Sales و Purchase
class SalesInvoiceService {
    protected function validateStockAvailability($details) { /* ... */ }
}
class PurchaseReturnService {
    protected function validateStockAvailability($details) { /* ... */ }
}

// ✅ مصدر واحد
class InventoryService {
    public function validateStockAvailability($details): void {
        // منطق مشترك
    }
}
```

---

### 4. Performance First — الأداء أولاً

**هدف النظام: كل عملية < 200ms.**

**القواعد العشر للأداء:**

1. **لا N+1 queries** — استخدم `with()` أو `load()`
2. **لا `SELECT *`** على جداول كبيرة — حدد الأعمدة
3. **Pagination إلزامي** — لا `.get()` بدون limit
4. **Batch queries** — عند الحاجة لبيانات متعددة
5. **Bulk inserts** — عند إدراج >10 صفوف
6. **Indexes مدروسة** — على أعمدة البحث والفرز
7. **Cache للبيانات الثابتة** — الإعدادات، القوائم
8. **Queue للعمليات الثقيلة** — التقارير، الإرسال
9. **Atomic operations** — `UPDATE ... SET x = x + 1`
10. **قياس مستمر** — Telescope + Debugbar

**قاعدة القياس:** لا تحسّن بدون قياس. كل تحسين يجب أن يكون مدعوماً بأرقام.

---

### 5. Type Safety — أمان الأنواع

**استخدم الأنواع بقدر الإمكان:**

```php
// ❌ ضعيف
public function create($data) { ... }

// ✅ قوي
public function create(array $data): SalesInvoice { ... }

// ✅ أقوى — DTO
public function create(CreateSalesInvoiceDTO $dto): SalesInvoice { ... }
```

**Enums بدل الثوابت:**

```php
// ❌ قديم
class SalesInvoice {
    const PAYMENT_CREDIT = 1;
    const PAYMENT_CASH = 2;
}

// ✅ حديث
enum PaymentMethod: int {
    case Credit = 1;
    case Cash = 2;
}
```

---

### 6. Explicit over Implicit — الصريح أفضل من الضمني

**الكود يجب أن يقول ماذا يفعل بوضوح:**

```php
// ❌ ضمني — يخفي عملية DB
$invoice->total = $invoice->items->sum('total') - $invoice->discount;

// ✅ صريح
$itemsTotal = $invoice->details->sum(fn($d) => $d->quantity * $d->price);
$invoice->items_total = $itemsTotal;
$invoice->discount_total = $invoice->details->sum('discount');
```

```php
// ❌ Observer يخفي منطقاً حرجاً
class SalesInvoiceObserver {
    public function created($invoice) {
        // ينشئ حركة مخزون... منطق خطير مخفي!
    }
}

// ✅ Service صريح
$invoice = $this->service->create($data);
// في Service:
$this->syncInventoryMovement($invoice);  // واضح
```

## 📋 الأنماط المعيارية (Patterns)

### Pattern 1: Service Class

**متى تستخدمه:**
- عملية تشمل أكثر من Model واحد
- عملية لها منطق عمل حقيقي
- عملية تحتاج transaction

**القالب:**

```php
<?php

namespace App\Services\{Domain};

use App\Services\BaseService;
use App\Services\SequenceService;

class {Entity}Service extends BaseService
{
    public function __construct(
        private readonly SequenceService $sequences,
        // ... services أخرى
    ) {}

    /**
     * قائمة مع pagination
     */
    public function list(array $filters): LengthAwarePaginator
    {
        return {Entity}::query()
            ->with(['relations...'])
            ->when($filters['search'] ?? null, fn($q, $s) => $q->search($s))
            ->orderByDesc('{entity}_id')
            ->paginate($filters['per_page'] ?? 50);
    }

    /**
     * إيجاد واحد
     */
    public function find(int $id): {Entity}
    {
        return {Entity}::with([...])->findOrFail($id);
    }

    /**
     * إنشاء
     */
    public function create(array $data): {Entity}
    {
        return $this->transaction(function () use ($data) {
            // 1. validations
            // 2. create header
            // 3. create details (bulk)
            // 4. side effects (inventory, journal)
            return $entity->fresh();
        }, '{Entity}::create');
    }

    /**
     * تحديث
     */
    public function update(int $id, array $data): {Entity}
    {
        return $this->transaction(function () use ($id, $data) {
            $entity = {Entity}::findOrFail($id);

            // 1. revert side effects
            // 2. update
            // 3. re-apply side effects

            return $entity->fresh();
        }, '{Entity}::update');
    }

    /**
     * حذف
     */
    public function delete(int $id): void
    {
        $this->transaction(function () use ($id) {
            $entity = {Entity}::findOrFail($id);

            // 1. revert side effects
            // 2. delete (soft)

        }, '{Entity}::delete');
    }
}
```

**قواعد الـ Service:**
1. ✅ يرث من `BaseService`
2. ✅ يستخدم `transaction()` للعمليات الكتابية
3. ✅ constructor injection (لا `new`)
4. ✅ `array $data` بدل `Request` مباشرة
5. ✅ يُرجع Models، لا `Response`
6. ✅ الاستثناءات من نوع domain (`ValidationException`, `RuntimeException`)
7. ✅ كل عملية private ≤ 50 سطر

### Pattern 2: Form Request

**متى تستخدمه:**
- أي عملية تُدخل بيانات من المستخدم
- عند وجود قواعد تحقق معقدة

**القالب:**

```php
<?php

namespace App\Http\Requests\{Domain};

use Illuminate\Foundation\Http\FormRequest;

class Store{Entity}Request extends FormRequest
{
    public function authorize(): bool
    {
        return true;  // Single user حالياً
        // مستقبلاً: return $this->user()->can('create', {Entity}::class);
    }

    public function rules(): array
    {
        return [
            'field_1' => ['required', 'string', 'max:255'],
            'field_2' => ['nullable', 'numeric', 'min:0'],
            'details' => ['required', 'array', 'min:1'],
            'details.*.field' => ['required', 'integer', 'exists:table,col'],
        ];
    }

    /**
     * قواعد معقدة تحتاج منطق
     */
    public function withValidator($validator): void
    {
        $validator->after(function ($v) {
            // منطق معقد — يعتمد على حقول أخرى
            if ($this->input('x') === 'y' && $this->input('z') !== 'w') {
                $v->errors()->add('x', 'خطأ منطقي');
            }
        });
    }

    public function messages(): array
    {
        return [
            'field_1.required' => 'رسالة مخصصة',
        ];
    }

    public function attributes(): array
    {
        return [
            'field_1' => 'اسم الحقل',
        ];
    }
}
```

**قواعد الـ FormRequest:**
1. ✅ كل عملية Store لها Request
2. ✅ كل عملية Update لها Request (يرث من Store إن أمكن)
3. ✅ `messages()` بالعربية دائماً
4. ✅ `attributes()` لتسمية الحقول
5. ✅ `withValidator()` للمنطق المعقد
6. ❌ لا `DB::` في FormRequest
7. ❌ لا منطق عمل — فقط تحقق

### Pattern 3: Model

**القالب:**

```php
<?php

namespace App\Models\{Domain};

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\SoftDeletes;
use Illuminate\Database\Eloquent\Factories\HasFactory;

class {Entity} extends Model
{
    use HasFactory, SoftDeletes;

    protected $table = '{entities}';
    protected $primaryKey = '{entity}_id';
    public $incrementing = true;
    protected $keyType = 'int';

    protected $fillable = [
        // قائمة صريحة — لا $guarded = []
    ];

    protected $casts = [
        'status'      => {Entity}Status::class,
        'amount'      => 'decimal:6',
        'metadata'    => 'array',
        'created_at'  => 'datetime',
        'deleted_at'  => 'datetime',
    ];

    // ══════════════════════════════════════════════
    //  Relations
    // ══════════════════════════════════════════════

    public function account()
    {
        return $this->belongsTo(CharAccount::class, 'account_id', 'accountID');
    }

    public function details()
    {
        return $this->hasMany({Entity}Detail::class, '{entity}_id', '{entity}_id');
    }

    // ══════════════════════════════════════════════
    //  Scopes
    // ══════════════════════════════════════════════

    public function scopeActive($query)
    {
        return $query->where('status', 1);
    }

    public function scopeSearch($query, string $term)
    {
        return $query->where(function ($q) use ($term) {
            $q->where('name', 'like', "%{$term}%")
              ->orWhere('code', 'like', "%{$term}%");
        });
    }

    public function scopeInDateRange($query, ?string $from, ?string $to)
    {
        return $query
            ->when($from, fn($q) => $q->where('created_at', '>=', $from))
            ->when($to, fn($q) => $q->where('created_at', '<=', $to));
    }

    // ══════════════════════════════════════════════
    //  Accessors & Mutators (بحذر — للأداء)
    // ══════════════════════════════════════════════

    // ⚠️ لا تكثر من Accessors — كل استدعاء = عملية
    // استخدم DB::raw أو احسب في Service بدلاً منها

    // ══════════════════════════════════════════════
    //  Helper Methods
    // ══════════════════════════════════════════════

    public function isActive(): bool
    {
        return $this->status === 1;
    }
}
```

**قواعد الـ Model:**
1. ✅ `$fillable` صريحة (لا `$guarded = []`)
2. ✅ `$casts` لكل الحقول الرقمية (`decimal:6`)
3. ✅ Enums للـ statuses
4. ✅ SoftDeletes للجداول الرئيسية
5. ✅ Scopes للاستعلامات الشائعة
6. ✅ Helper methods للحالات (isActive, isPosted)
7. ⚠️ لا Accessors كثيرة — تُبطئ الأداء
8. ❌ لا منطق عمل في Model
9. ❌ لا استدعاء Services من Model

### Pattern 4: Observer

**متى تستخدمه:**
- **Safety Net** لحذف مرتبطات (كما في SalesInvoiceObserver)
- أحداث بسيطة (تحديث `updated_at`)

**متى لا تستخدمه:**
- ❌ منطق عمل حقيقي → Service
- ❌ إنشاء حركات مخزون → Service صريح
- ❌ عمليات معقدة → Action

**القالب:**

```php
<?php

namespace App\Observers;

use App\Models\{Domain}\{Entity};

class {Entity}Observer
{
    /**
     * Safety Net — يعمل فقط لو نُفّذ الحذف خارج Service
     */
    public function deleted({Entity} $entity): void
    {
        // منطق التنظيف
    }
}
```

**قواعد الـ Observer:**
1. ✅ استخدمه كـ Safety Net فقط
2. ✅ استخدم `app(Service::class)` بدل constructor injection
3. ✅ وثّق "لماذا هذا Observer موجود"
4. ❌ لا تضع فيه منطقاً حرجاً
5. ❌ لا تفترض ترتيب الاستدعاء

### Pattern 5: Enum

**القالب:**

```php
<?php

namespace App\Enums;

enum InvoiceStatus: int
{
    case Draft      = 1;
    case Posted     = 2;
    case Cancelled  = 3;

    public function label(): string
    {
        return match($this) {
            self::Draft     => 'مسودة',
            self::Posted    => 'مُرحَّل',
            self::Cancelled => 'ملغى',
        };
    }

    public function color(): string
    {
        return match($this) {
            self::Draft     => 'secondary',
            self::Posted    => 'success',
            self::Cancelled => 'danger',
        };
    }

    public function canEdit(): bool
    {
        return $this === self::Draft;
    }

    public function canDelete(): bool
    {
        return $this !== self::Posted;
    }

    public static function options(): array
    {
        return array_map(
            fn($c) => ['value' => $c->value, 'label' => $c->label()],
            self::cases()
        );
    }
}
```

**الاستخدام في Model:**
```php
protected $casts = [
    'status' => InvoiceStatus::class,
];

// في الكود:
if ($invoice->status === InvoiceStatus::Draft) {
    // ...
}

// للعرض:
$invoice->status->label();  // 'مسودة'
```

## 🔒 قواعد صارمة (Hard Rules)

### القاعدة 1: لا `DB::` في Controllers

```php
// ❌ ممنوع
class SalesInvoiceController extends Controller
{
    public function store(Request $request)
    {
        DB::transaction(function () use ($request) {
            // ...
        });
    }
}

// ✅ صحيح
public function store(StoreSalesInvoiceRequest $request)
{
    $invoice = $this->service->create($request->validated());
    return $this->createdResponse($invoice);
}
```

**السبب:** فصل الطبقات + اختبار أسهل.

---

### القاعدة 2: لا `Validator::make` في Controllers

```php
// ❌ ممنوع
public function store(Request $request)
{
    $validator = Validator::make($request->all(), [...]);
    if ($validator->fails()) { ... }
}

// ✅ صحيح
public function store(StoreSalesInvoiceRequest $request) { ... }
```

**السبب:** Controller نظيف + قابلية إعادة استخدام.

---

### القاعدة 3: لا N+1 Queries

```php
// ❌ ممنوع — N+1
$invoices = SalesInvoice::limit(50)->get();
foreach ($invoices as $invoice) {
    echo $invoice->customerAccount->accName;  // Query لكل فاتورة!
}

// ✅ صحيح — Eager Loading
$invoices = SalesInvoice::with('customerAccount')->limit(50)->get();
```

**السبب:** أداء + تجنب 50 query إضافية.

---

### القاعدة 4: لا `SELECT *` على جداول كبيرة

```php
// ❌ ممنوع
SalesInvoice::where(...)->get();

// ✅ صحيح
SalesInvoice::select(['id', 'invoice_number', 'invoice_date'])
    ->where(...)
    ->limit(50)
    ->get();
```

**السبب:** تقليل نقل البيانات + تحسين الذاكرة.

---

### القاعدة 5: لا `whereHas` للبحث على بيانات كبيرة

```php
// ❌ ممنوع على مليون سجل
SalesInvoice::whereHas('customerAccount', function ($q) use ($search) {
    $q->where('accName', 'like', "%{$search}%");
})->get();

// ✅ صحيح — JOIN
SalesInvoice::query()
    ->leftJoin('characcount', 'sales_invoices.account_id', '=', 'characcount.accountID')
    ->where('characcount.accName', 'like', "{$search}%")
    ->select('sales_invoices.*')
    ->paginate(50);
```

**السبب:** `whereHas` يُنشئ subquery. JOIN أسرع.

---

### القاعدة 6: لا `lockForUpdate` للترقيم

```php
// ❌ ممنوع — Race condition
$last = SalesInvoice::lockForUpdate()->orderByDesc('id')->first();
$next = $last ? $last->number + 1 : 1;

// ✅ صحيح
$next = $this->sequences->next('sales_invoice');
```

**السبب:** `lockForUpdate` لا يمنع فتحتين متزامنتين.

---

### القاعدة 7: لا Cache ثابت (static) داخل Service

```php
// ❌ ممنوع — يُرجع بيانات قديمة
public function availableQuantity($itemId) {
    static $cache = [];
    if (isset($cache[$itemId])) return $cache[$itemId];
    // ...
}

// ✅ صحيح — قراءة مباشرة من DB (سريعة)
public function availableQuantity($itemId) {
    return InventoryBalance::where('item_id', $itemId)->value('quantity') ?? 0;
}
```

**السبب:** static cache يعيش لكل الطلب — لا يُبطَل عند التعديل.

---

### القاعدة 8: كل عملية كتابية داخل transaction

```php
// ❌ ممنوع
public function create($data) {
    $invoice = SalesInvoice::create($data);
    $this->saveDetails($invoice, $data['details']);  // لو فشل، الفاتورة بقت!
    return $invoice;
}

// ✅ صحيح
public function create($data) {
    return DB::transaction(function () use ($data) {
        $invoice = SalesInvoice::create($data);
        $this->saveDetails($invoice, $data['details']);
        return $invoice;
    });
}
```

**السبب:** سلامة البيانات + Rollback تلقائي.

---

### القاعدة 9: كل جدول له SoftDeletes

```php
// في Migration
$table->softDeletes();
$table->unsignedBigInteger('created_by')->nullable();
$table->unsignedBigInteger('updated_by')->nullable();
$table->unsignedBigInteger('deleted_by')->nullable();

// في Model
use SoftDeletes;
```

**السبب:** ERP يحتاج Audit trail + استرجاع.

**الاستثناء:** جداول Join (pivot).

---

### القاعدة 10: كل Migration قابلة للـ rollback

```php
public function down(): void
{
    Schema::dropIfExists('table_name');
}
```

**السبب:** قدرة الاستعادة في الطوارئ.

### Transactions

```php
// ✅ نموذج صحيح
return DB::transaction(function () use ($data) {

    // 1. Pre-flight checks
    $this->validateSomething($data);

    // 2. Create/Update main record
    $entity = Model::create($data);

    // 3. Side effects
    $this->syncRelated($entity);

    // 4. Return fresh
    return $entity->fresh(['relation']);

}, attempts: 1);  // ← عدد محاولات إعادة التنفيذ
```

**`attempts: 1`** — لا نعيد المحاولة (منع التكرار). للـ deadlocks استخدم `attempts: 3`.

---

### Error Handling

```php
// ✅ في Service — throw domain exceptions
if ($available < $qty) {
    throw ValidationException::withMessages([
        "details.{$i}.quantity" => "الكمية المتوفرة {$available} أقل من المطلوب {$qty}",
    ]);
}

// ✅ في Controller — لا try/catch (Laravel Handler يتولى)
public function store(StoreRequest $request)
{
    $entity = $this->service->create($request->validated());
    return $this->createdResponse($entity);
}

// ✅ Exception مخصص للسياق
class InsufficientStockException extends DomainException
{
    public static function forItem(int $itemId, float $available, float $requested): self
    {
        return new self(
            "الكمية المتوفرة ({$available}) أقل من المطلوب ({$requested}) للصنف #{$itemId}"
        );
    }
}
```

// ✅ معلومات مفيدة
Log::info('Sales invoice created', [

## 🚫 Anti-patterns — ما يجب تجنبه

### 1. Fat Controller

```php
// ❌ 400 سطر في Controller
class SalesInvoiceController extends Controller
{
    public function store(Request $request)
    {
        $validator = Validator::make($request->all(), [...]);
        // ... 300 سطر
    }
}

// ✅ 80 سطر
class SalesInvoiceController extends Controller
{
    public function store(StoreSalesInvoiceRequest $request)
    {
        $invoice = $this->service->create($request->validated());
        return $this->createdResponse($invoice);
    }
}
```

---

### 2. Fat Model

```php
// ❌ منطق عمل في Model
class SalesInvoice extends Model
{
    public function createWithInventory($data) { ... }
    public function postToJournal() { ... }
}

// ✅ Model للبيانات فقط
class SalesInvoice extends Model
{
    public function details() { ... }
    public function isPosted(): bool { ... }
}
```

---

### 3. Anemic Service

```php
// ❌ Service يمرر فقط
class SalesInvoiceService
{
    public function create($data) {
        return SalesInvoice::create($data);
    }
}

// ✅ Service فيه منطق
class SalesInvoiceService
{
    public function create($data) {
        return DB::transaction(function () use ($data) {
            $this->validateStockAvailability($data['details']);
            $invoice = SalesInvoice::create([...]);
            $this->saveDetails($invoice, $data['details']);
            $this->syncInventoryMovement($invoice);
            return $invoice->fresh();
        });
    }
}
```

---

### 4. Static Cache في Service

```php
// ❌ static $cache يعيش لكل الطلب
class InventoryService
{
    public function getBalance($id) {
        static $cache = [];
        if (isset($cache[$id])) return $cache[$id];
        return $cache[$id] = Balance::find($id)->quantity;
    }
}
```

**لماذا سيء:** لا يُبطَل عند التعديل → بيانات قديمة.

---

### 5. Query في Loop

```php
// ❌ N queries
foreach ($invoices as $invoice) {
    $customer = Customer::find($invoice->customer_id);
}

// ✅ 1 query
$customerIds = $invoices->pluck('customer_id');
$customers = Customer::whereIn('id', $customerIds)->get()->keyBy('id');
```

---

### 6. Mass Assignment غير آمن

```php
// ❌ $guarded = []
protected $guarded = [];

// ✅ $fillable صريحة
protected $fillable = ['name', 'email', 'status'];
```

---

### 7. Accessor في Loop

```php
// ❌ Accessor يُستدعى لكل صف
foreach ($invoices as $invoice) {
    $total = $invoice->total_in_invoice_currency;  // Accessor
}

// ✅ احسب في SQL أو مرة واحدة
$invoices->each(function ($inv) {
    $inv->total = $inv->items_total - $inv->discount_total;
});
```
